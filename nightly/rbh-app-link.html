RBH 앱 링크 — Network --rbh 의 WebRTC 통로 ​

src/Network/RbhAppLink.{h,cpp}. 휴머노이드 모드에서 컨트롤러 앱(gui/)과 웹 대시보드(src/Network/ui/, 같은 바이너리에 내장)가 붙는 길. 앱 쪽 짝은 gui/docs/humanoid.md.

왜 두 번째 링크인가 ​

RbhPodoLink(TCP 8000, Qt RBHGUI)는 공유메모리를 통째로 보낸다 — LAN_PODO2GUI 105,920 B × 100 Hz ≈ 85 Mbit/s(2026-09-18 컴파일해 잼). 유선 아니면 못 버티고 LTE 는 불가. 앱은 사족처럼 WebRTC 라, 같은 시그널링에 DataChannel rbh 하나를 두고 필요한 값만 보낸다(20 Hz, 약 20 KB/s). TCP 8000 은 그대로 둔다(유선 튜닝용).

구성 ​

클래스역할
RbhHttpServer--rbh 의 :8080. health·version·robot/features(robot:"rbh")·robot/serial_number·webrtc offer/hangup + 내장 대시보드(cmrc ui, 4족과 같은 바이트) . 사족 HttpServer 는 사족 SHM 을 읽어서 못 띄운다. 계정은 기본 rb 에 rbh 를 하나 더 받는다(addAuthUser, 권한 차이 없음)
RbhWebRTCServer세션 1 개(setSingleSession) — 명령이 AL 당 공유메모리 슬롯 하나를 쓴다. 랑데부 시그널러도 붙인다(원격)
RbhPeerSession라벨 rbh 만 바인드. 앱이 여는 사족 채널(command·motion-state·log·estop)은 무시
RbhAppLink공유메모리 ↔ 앱. 상태 20 Hz, 명령 큐, 패드 프레임을 RbhOperatorInput::applyGamepad 로(Network 가 JOYData 와 1 초 데드맨을 소유), 요청 시 세부정보 20 Hz

프로토콜(rbh 채널) ​

  • 로봇→앱: {"t":"hello",robot,model,joints,policies[]}(열릴 때) · {"t":"s",q,dq,tau,qref,cur,tb,tm,con,err,rpy,gyro,bat,sw,ctl,al,rng,vxmax,joy,q2}(20 Hz)
    • vxmax = Locomotion RL 전진 상한(십자키 ↑↓로 0.25 씩, Motions_RL.cpp → customVariable[19]). 걷기 중에만 값이 있다
  • 로봇→앱(요청 시): {"t":"d", mpos,mref,cref,tref,mvel,mtor,jacc,vref,kp,kd,mkp,mkd,st0,pvl, state,ctrl,cmd, walk, cvar[20], jlim, ft,fth,imu,body,pdu}(20 Hz) — Qt RBHGUI 가 보여주는 나머지 전부(MOTOR 탭 열, 작업공간 3 벌, 보행 상태, 커스텀 변수, FT, PDU). {"t":"sub","detail":true|false} 로 켜고 끈다. 요약(약 20 KB/s)만이 LTE 에서 쓸 수 있는 크기라, 세부정보는 Details·Plots 페이지가 열려 있을 때만 흐른다(접속이 끊기면 자동 해제)
  • 앱→로봇: {"t":"cmd",target,cmd,i[],f[],c[],d[],s} — COMMAND_STRUCT 하나. s = USER_PARA_CHAR 문자열(정책 경로), 128 자 이상은 거부
  • 앱→로봇: 40 B 바이너리 = rbh::LAN_JOYSTICK(axisLeftX, axisLeftY, axisRightX, axisRightY, LT, RT, buttons[16]) → RbhOperatorInput::applyGamepad. ⚠X·Y 순서 — 뒤바꾸면 "전진"이 "옆걸음"이 된다(2026-09-22 대시보드에서 실제로 났던 버그)

웹 대시보드 (http://<로봇IP>:8080) ​

4족과 같은 src/Network/ui/ 를 cmrc 로 바이너리에 박아 준다 — 주소·포트·인증·SPA 폴백 규칙이 4족과 같고, Network 하나만 빌드·배포하면 UI 가 따라온다. main.js 가 부팅 때 /api/robot/features 를 물어 robot:"rbh" 면 휴머노이드 메뉴로 갈아탄다(4족 메뉴는 4족 공유메모리를 읽어 휴머노이드에선 전부 0 으로 그리므로 뺀다).

공용: gamepad.js(물리 패드 — 축은 패드가 움직일 때만 화면 스틱을 이기고, 버튼은 화면∪패드, LT/RT 는 패드. 브라우저는 버튼을 한 번 눌러야 패드를 노출한다), joystick.js(가상 스틱 — control.js 의 4족 스틱은 제어권 로직과 엉켜 있어 아직 따로다, 세 번째 사본은 만들지 말 것), rtc.js 의 rbh 채널(onRbh/sendRbh/sendRbhPad, hello 는 기억해 늦게 연 페이지에도 준다).

  • 개발은 빌드 없이: node gui/tools/rbq-web-proxy.js --robot 127.0.0.1 --port 8090 --dist ../src/Network/ui → :8090. 로봇 반영은 Network 증분 빌드(몇 분).
  • CMakeLists.txt 의 file(GLOB … CONFIGURE_DEPENDS "ui/*") — 이게 없으면 ui/ 에 새 파일을 추가해도 증분 빌드에 조용히 빠진다(2026-09-21 Details 페이지가 404 로 처음 드러남. 4족에도 같은 함정이었다).
  • 레이아웃이 흔들리지 않게: 값이 바뀌는 글자는 고정폭·자릿수 고정(+0.00, 0x0000), 알약·안내 줄은 최소 폭/높이, 버튼 :active 에 transform 금지.
  • 정적 파일은 Cache-Control: no-cache + ETag: "<GIT_VERSION>"(4족 HttpServer·RbhHttpServer 둘 다, 2026-09-22). 새 펌웨어를 띄운 순간 새 UI 가 나와야 하는데, 헤더가 없던 시절엔 같은 주소의 옛 main.js 가 남아 RBQ10 메뉴가 보였다(Gurban PC 는 Ctrl+Shift+R 로, 다른 PC 는 시크릿 창으로만 해결됐다). 같은 빌드면 If-None-Match 로 304. main.js 는 뜰 때 이 출처의 서비스 워커를 전부 해제한다 — 같은 주소에 앱 웹을 서빙했던 흔적이 파일을 가로챌 수 있어서.
  • 앱(gui/) 웹 빌드를 로봇이 서빙하는 길은 만들었다가 뺐다(2026-09-21). 앱은 APK/AAB 로 가고, 브라우저는 이 대시보드가 맡는다.

원버튼 업데이트 (Overview → Software) ​

4족 OTA(src/rcl/Ota.cpp, WS :56785)를 그대로 쓴다 — 브라우저가 받아서 로봇에 밀어 넣는 구조라 로봇은 인터넷도 자격증명도 필요 없다.

릴리스: release_rbh.bash ─► tar.gz 를 gpg AES-256 으로 봉인한 RBH-<tag>.rbh ─► GitHub RainbowRobotics/RBH (private) + s3://rainbow-rbh/<tag>/RBH-<tag>.rbh(+.sha256), index.json
브라우저: index.json 으로 최신 확인 → .rbh 다운로드 → OTA WS 로 청크 전송(sha256 동봉)
로봇:    sha256 대조 → gpg 로 봉인 해제(비번은 Ota.cpp 의 것, 변조·위조면 여기서 실패) → 해제(최상위 RBH-<tag>/ 하나) → scripts/deploy.bash --local → Motion SIGTERM → 런처가 새 빌드로 재기동
브라우저: /api/version 이 바뀔 때까지 2 초 간격 폴링(3 분 상한) → "Updated to vX"
  • S3 는 RBH 전용 버킷 rainbow-rbh(ap-northeast-2). RBQ 의 rainbow-rbq 와 섞지 않는다 — 공개 읽기 정책·GET/HEAD CORS·버전관리는 그쪽과 동일하게 맞췄다(2026-09-22 생성). private GitHub 저장소 문제를 이렇게 피한다: 자산은 S3 에서, 소스·릴리스 노트는 GitHub 에.
  • 파일명이 곧 명령이다: RBH-<tag>.rbh 만 받는다(Ota::isAcceptableName). RBH-*.tar.gz·zip 은 이름에서 거부(4족은 여전히 RBQ-*.zip/.tar.gz).
  • 봉인(.rbh) = 위조 방어 (2026-09-22). 로봇 PC 는 SSH·HDMI 없이 대시보드로만 배포하는데 deploy.bash 가 sudo 로 돌기 때문에, 아무 tar 나 들어가면 SSID 비번 변경 같은 게 가능하다. .rbh 는 tar.gz 를 gpg 대칭(AES-256) 으로 감싼 것이고 비번은 rcl/Ota.cpp 의 kPassphraseObfuscated(4족 OTA zip 과 같은 값, .github/scripts/ota_passphrase.bash 가 되짚는다). 비번 없이는 만들 수도 고칠 수도 없다(gpg MDC 가 한 바이트 변조도 잡는다). 4족 zip 을 그대로 안 쓴 이유: ZipCrypto 는 알려진 평문(ELF 헤더·#!/bin/bash)으로 키를 복원해 위조가 가능하다 — 4족 문서도 "가림막이지 변조 방어가 아니다" 라고 적고 있다. 위협 모델은 "로봇을 물리적으로 뜯으면 비번이 나온다" 까지 감수(사용자 결정). 개발자가 로컬 빌드를 넣으려면 같은 스크립트로 봉인해야 한다: bash .github/scripts/ota_passphrase.bash | gpg --batch --pinentry-mode loopback --passphrase-fd 0 --symmetric --cipher-algo AES256 -o RBH-<tag>.rbh RBH-<tag>.tar.gz. 로봇엔 gpg 가 있어야 한다(우분투 데스크톱 기본).
  • 패키지는 최상위 디렉터리 하나(RBH-<tag>/)여야 하고 안에 scripts/deploy.bash 가 있어야 한다 — 둘 다 release_rbh.bash 가 만든다. 로봇 전용 트리다(bin-x86_64/ + scripts/{deploy.bash, RBH.bash, start_motion.bash}, 2026-09-23). ~/RBH.bash 는 없을 때만 깔린다.
  • 자동 재기동은 Ota::setRestartAfterDeploy(true) — --rbh 의 Network 만 켠다. 배포 성공 프레임을 보낸 1.5 초 뒤: 실로봇(rbh.service 활성)은 재부팅한다(2026-09-23) — Motion 만 내리면 옛 Daemon 이 살아 있어 새 Motion 이 건너뛰었다(TODO 알려진 버그 13). 그 밖(개발 PC 의 시뮬)은 절대 재부팅하지 않고 부모(Motion)에 SIGTERM — start_motion.bash 의 while true 루프가 새 바이너리를 띄운다. 런처 없이 손으로 띄운 Motion 은 그냥 죽고 끝이다. 대시보드는 새 버전이거나, 끊겼다가 다시 응답하면 끝으로 본다(같은 버전 재설치).
  • Ota 는 봉인 패키지(.rbh)면 deploy.bash --local --rbh 를 돌려 $HOME/rbh_ws/ 에 쓴다 — 로봇의 실행 트리가 거기여야 한다(RBH.bash 의 기본 RBH_WS). 개발 PC 에선 그 경로가 실행 트리가 아니라 버전이 안 바뀐 것처럼 보인다.
  • 오프라인 현장: 같은 카드의 [Install a file…] 로 받아 둔 RBH-<tag>.rbh 를 올린다. 사이드카가 없어 sha256 검증은 건너뛴다(봉인 검사는 그대로).
  • 브라우저 쪽은 crypto.subtle 을 쓰지 않는다 — http://192.168.0.10:8080 은 보안 컨텍스트가 아니라 없다. 검증은 로봇이 한다.
  • 로봇에는 resources/ 가 없다(deploy.bash --rbh 가 안 보낸다, 2026-09-23). 로봇별 상태는 /root/.config/RBH/ 에 있다 — calibration.ini(Daemon 이 쓴다, 예전 /etc/rbh/ 는 Daemon 이 한 번 옮긴다)와 선택 사항인 robot_config.yaml (selectedRobot, 없으면 RBH_SCH_v1). resources/rbh 는 시뮬만 쓴다 — Mujoco 의 mjcf/, 그리고 시뮬의 로봇 선택 resources/rbh/robot_config.yaml(있으면 /root/.config/RBH 보다 먼저 읽는다).
  • 로봇 모델·파라미터·RL 정책은 바이너리에 들어간다(cmrc, 2026-09-22) — 예전처럼 robot_models/ 가 빠져서 Humanoid 가 명령을 조용히 무시하는 일은 없다. 정책은 hello.policies[].path = <kind>/<name> 로 고른다. Qt RBHGUI 가 붙어 있는 것도 같은 증상을 낸다(RbhPodoLink 가 100 ms 마다 슬롯을 덮음) — 둘을 가르는 법: ss -tnH state established '( sport = :8000 )' 가 비어 있으면 Qt 는 아니다.
  • 대시보드 Control 을 떠날 때(humanoid.js cleanup) 버튼·축을 비우고 0 프레임 3장을 먼저 보낸 뒤 25 ms 타이머를 끈다 — 순서가 반대면 누르고 있던 START 가 로봇의 마지막 프레임으로 남아 데드맨 1 초 동안 세어져 걷기 시작할 수 있다(AI 리뷰 #763). 앱(humanoid.tsx)도 같은 이유로 clearInputs().
  • ⚠런처 루프는 하나만. start_motion.bash 의 while true 가 둘 이상 살아 있으면 먼저 있던 루프가 자기 cwd 의(옛) 바이너리를 되살려 업데이트가 적용된 것처럼 보이지 않는다(2026-09-22 실측: mv 로 옮긴 디렉터리를 옛 루프가 따라가 A 를 재기동). 시뮬을 다시 띄울 땐 ps -eo pid,args | awk '$2=="bash" && $3 ~ /^scripts\/start_/' 로 루프부터 지운다 — pkill -f start_motion 은 자기 셸까지 죽인다.

함정 ​

  • ⚠명령은 슬롯이 비었을 때만 쓴다(USER_COMMAND 가 NO_ACT 0 / BIPEDCONTROL_NO_ACT 100). AL 은 100 ms 마다 슬롯을 읽고 NO_ACT 로 되돌린다 — 읽기 전에 덮어쓰면 앞 명령이 조용히 사라진다. RbhPodoLink 는 100 ms 마다 무조건 쓴다. 1 초 넘게 안 비면 경고 후 덮는다.
  • ⚠패드 끊김 = 정지는 RbhOperatorInput(Network) 이 맡는다: 1 초 무수신이면 JOYData 를 0 으로. 앱·무선이 죽어도 마지막 입력을 쥐고 있지 않다. 로봇에 USB 패드가 꽂혀 있으면 그쪽이 JOYData 를 덮는다 — 둘을 동시에 쓰지 않는다.
  • 패드 버튼 배치는 Humanoid 가 읽는 순서다(앱·대시보드가 맞춰 보낸다): A0 B1 X2 Y3, 십자키 ↑4 ↓5 ←6 →7, LB8 L3 9 RB10 R3 11, START14 BACK15.
  • ⚠접속은 한 번에 하나(setSingleSession) — 창을 두 개 열면 새 쪽이 옛 쪽을 끊고, 옛 쪽이 재접속하며 다시 끊는 핑퐁이 난다(2026-09-22 실측, 약 17 초 주기). 조종 중에 누가 Details 를 보려고 열기만 해도 조종이 끊긴다. 4족처럼 다중 접속 + 조종권으로 바꾸는 것이 숙제.
  • ⚠M2G(작업공간·보행) 값은 Humanoid 가 동작을 수행할 때만 채워진다 — 새로 띄운 뒤 아무것도 안 하면 전부 0. 0 이면 로봇이 대기 중이란 뜻이다.
  • 정책은 <kind>/<name>(예: locomotion/latest) — Humanoid 에 컴파일돼 들어간 것만 고를 수 있다(목록: rcl/rbh/Policies.h). 경로가 짧아 USER_PARA_CHAR 127 자 제한에 걸릴 일이 없다.
  • 관절 수 28 은 상수다(JointParams 는 static init 에 yaml 을 읽어 Network 에 링크하지 않았다). 이름은 앱이 갖는다(gui/src/modules/rbh/store.ts RBH_JOINTS).
  • 로봇 식별 robot/serial_number 가 없으면 앱이 "로봇이 아님"으로 보고 안 붙는다(프록시 /local-sim·probeLan 둘 다 이것).
