Gazebo ​

소개 ​

RBQ 4족 보행 로봇을 위한 오픈소스 Ignition Gazebo (Fortress) 시뮬레이터.

Gazebo는 RBQ 소프트웨어 스택 전체를 실행하여, SLAM 연구, 자율주행 테스트, 실기에서 하던 모든 테스트를 시뮬레이션에서 할 수 있게 합니다. 또한 센서 데이터를 ROS 2로 브리지하므로, 외부 노드(예: SLAM)가 시뮬레이션된 IMU, LiDAR, TF, 관절 상태를 구독할 수 있습니다.

Gazebo

구성 ​

경로설명
src/시뮬레이터 소스 → bin/rbq_gazebo
resources/월드, 로봇/센서 URDF, 메시
ros2/src/sensor_bridge/colcon 패키지: 브리지 launch, RViz 설정, DDS xml
scripts/빌드 / 실행(gazebo.bash) / Docker 스크립트

RBQ 스택과 함께 실행 ​

설치

bash
# Clone
git clone https://github.com/RainbowRobotics/RBQ.git
cd RBQ

# 의존성 설치 (최초 1회)
cd rbq_simulator/rbq_gazebo && bash scripts/debian-dep.bash

# rbq_gazebo 빌드
bash scripts/build.bash
cd ../../

Local

scripts/sim.bash --no-sim 은 시뮬레이터 없이 RBQ 코어 SW만 띄우고, 준비되면 웹 UI(http://127.0.0.1:8080, rb / rainbow2026)를 엽니다. 브라우저를 열지 않으려면 --no-gui 를 붙입니다. 그다음 시뮬레이터를 띄웁니다:

사족

bash
bash scripts/sim.bash --vision --no-sim
cd rbq_simulator/rbq_gazebo
bash scripts/gazebo.bash

휠타입 RBQ

bash
bash scripts/sim.bash --vision --no-sim -r wheel
cd rbq_simulator/rbq_gazebo
bash scripts/gazebo.bash --wheel

한 번에 실행 — --core 를 붙이면 두 단계를 한 번에 합니다. 시뮬레이터 스크립트가 시뮬레이터에 준 로봇 변형, 라이다, -i 로 RBQ 코어 SW(scripts/sim.bash --no-sim)도 함께 띄웁니다. --vision, --no-gui 는 위와 같습니다. 코어 SW는 자기 터미널 탭에서 돌고 시뮬레이터를 멈춰도 계속 돕니다. 멈추려면 그 탭들을 닫습니다.

bash
cd rbq_simulator/rbq_gazebo
bash scripts/gazebo.bash --core --vision
bash scripts/gazebo.bash --core --vision --wheel

Docker

시뮬레이터를 Docker 안에서 띄우고 호스트의 RBQ 스택에 붙입니다:

bash
bash scripts/sim.bash --vision --no-sim
cd rbq_simulator/rbq_gazebo
bash scripts/docker/run.bash            # 사족
bash scripts/docker/run.bash --wheel    # 휠타입 RBQ

run.bash 는 --headless, --build, --no-check 를 처리하고 나머지 인자는 시뮬레이터로 그대로 넘깁니다 — --wheel, --livox / --ouster, --world <이름> 모두 그대로 전달됩니다.

i

NOTE — DDS 네트워킹

시뮬레이터는 호스트 RBQ 스택과 루프백 인터페이스(lo)에서 DDS 도메인 0을 공유합니다. Docker에서는 --network host로 제공됩니다. 시뮬레이터는 한 번에 하나만 띄웁니다. MuJoCo, Gazebo, Isaac Sim은 같은 토픽을 씁니다.

옵션 ​

옵션의미
--wheel휠타입 RBQ (12관절 + 구동륜 4개). 기본은 사족
--livoxLivox Mid-360 x2 (앞 / 뒤). LiDAR 참조
--ousterOuster OS1-32 x1 (뒤 데크). LiDAR 참조
--world <name>불러올 월드. 기본 empty. 월드 참조
--headlessGazebo 창 없이 실행합니다
-i, --interface <name>DDS 네트워크 인터페이스. 기본 lo
--rvizgazebo.bash 전용. RViz 도 띄웁니다. ROS 2 참조
--no-rosgazebo.bash 전용. ROS 2 브리지와 RViz 없이 Gazebo 만 띄웁니다
--coregazebo.bash 전용. RBQ 코어 SW도 함께 띄우고 웹 UI를 엽니다. --vision 이면 Vision 스택도 띄우고, --no-gui 면 브라우저를 열지 않습니다
변형로봇모델
(없음)RBQ (사족) — 12관절resources/models/rbq10/
--wheel휠타입 RBQ — 12관절 + 구동륜 4개resources/models/rbq10_wheel/

gazebo.bash 가 같은 값을 센서 브리지에 variant:= 로 넘기므로 RViz 도 같은 URDF 를 불러옵니다.

i

참고 — RBQ 스택에도 같은 변형을 주세요

휠 상태와 지령은 SimInfo_.whl_joint / MotionRef_.whl_joint 로 오가므로 로봇쪽 Motion 도 같은 변형으로 떠야 합니다 — 저장소 루트에서 bash scripts/sim.bash -r wheel 로 스택을 띄우세요.

월드

월드--world비고
RBQ test worldempty (기본)계단, 장애물, 20° / 30° 경사로, 미끄러운 바닥, 도킹 스테이션

월드는 resources/worlds/ 의 SDF 파일이고, --world <이름> 은 resources/worlds/<이름>.sdf 를 불러옵니다. 처음 실행할 때 Gazebo 가 Fuel 모델을 내려받을 수 있습니다.

센서 ​

카메라

로봇 카메라 6대는 늘 모델에 있고 MuJoCo 와 같은 토픽으로 발행합니다. 그래서 Vision 스택(HAL)이 그대로 읽습니다:

센서카메라스트림
sensor_0–sensor_3하부 (앞, 중앙 앞, 중앙 뒤, 뒤)depth, IR
sensor_4전방depth, RGB
sensor_5후방depth, RGB

카메라마다 640 x 360, 15 fps입니다. 토픽은 rt/rbq/vision/sensor_N/<stream>/compressed 이고, 옆에 camera_info 와 tf 가 있습니다.

LiDAR

라이다는 옵트인입니다. 플래그를 주지 않으면 스폰되지 않습니다.

플래그LiDAR스캔
(없음)없음—
--livoxLivox Mid-360 x2, lidar_front (+35° 상향) / lidar_rear (−35° 상향)gpu_lidar
--ouster뒤 데크의 Ouster OS1-32 x1, lidar_ouster32 ch × 1024

gazebo.bash 는 같은 값을 센서 브리지에 lidar:= 로 넘깁니다. 그 결과 한 플래그로 셋이 함께 맞춰집니다:

  • Gazebo — 스폰 URDF 에 해당 라이다의 <visual>(하우징) + <sensor>(gpu_lidar) 가 스플라이스됨
  • TF — base_link → lidar_front | lidar_rear | lidar_ouster 정적 TF 발행
  • RViz — 같은 조합으로 생성된 URDF(rbq10_livox.urdf 등)를 불러 하우징까지 같이 표시

SLAM 에 넣으려면 RBQ 스택에도 같은 LiDAR 를 줍니다: bash scripts/sim.bash --slam --no-sim -p livox. 점군이 브리지로 오므로 --no-ros 는 쓰지 않습니다. Gazebo 에는 LiDAR 전용 IMU 와 점별 시간이 없어서, SLAM 이 읽는 프레임은 왜곡 보정(deskew)이 되지 않습니다.

IMU

몸체 IMU 는 매 제어 주기 로봇 상태와 함께 Motion 으로 가고, 브리지가 /rbq/imu/IMU_state(500 Hz)로도 발행합니다. LiDAR 전용 IMU 는 없습니다. Vision 스택(HAL)은 LiDAR 프레임에 몸체 IMU(rt/rbq/imu)를 씁니다.

ROS 2 ​

sensor_bridge는 루프백(lo)에서 ROS 2 도메인 0으로 발행합니다. 노드를 rbq_simulator/rbq_gazebo에서 다음 환경 변수와 함께 실행하세요 (브리지와 맞추려면 CycloneDDS를 사용해야 합니다):

bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_DOMAIN_ID=0
export CYCLONEDDS_URI=file://$(pwd)/ros2/src/sensor_bridge/config/cyclonedds_gazebo.xml

QoS는 ros_gz_bridge 기본값으로 모든 토픽이 Reliable · KeepLast 10 입니다 (토픽별 재정의는 ros2/src/sensor_bridge/config/bridge.yaml):

ROS 2 토픽타입비고
/clockrosgraph_msgs/msg/Clock시뮬 시각
/rbq/imu/IMU_statesensor_msgs/msg/Imu몸체 IMU
/rbq/lidar/lidar_front/pointssensor_msgs/msg/PointCloud2LiDAR 점군
/rbq/lidar/lidar_rear/pointssensor_msgs/msg/PointCloud2LiDAR 점군
/rbq/lidar/lidar_ouster/pointssensor_msgs/msg/PointCloud2LiDAR 점군
/tftf2_msgs/msg/TFMessage좌표 변환
/joint_statessensor_msgs/msg/JointState관절 상태

/tf 에는 서로 독립적인 두 체인이 흐릅니다. world → robot 은 rbq_gazebo 브릿지가 발행하는 Gazebo Ground Truth 포즈이고, local_world → base_link 는 RBQ SW 가 발행하는 상태추정 값(IMU + 레그 오도메트리, 부팅/리셋 시점이 원점)입니다. Ground Truth 를 base_link 가 아니라 robot 에 매단 것은 둘이 같은 부모 프레임을 두고 경합하지 않게 하기 위함입니다.

/rbq/odometry, /rbq/imu, /rbq/joint_states 는 브리지가 아니라 RBQ 스택이 DDS 로 직접 발행합니다. --sim 일 때는 시뮬레이션 시각을 쓰므로 use_sim_time 노드가 하나의 시간축으로 봅니다.

--rviz 는 번들 센서 뷰(ros2/src/sensor_bridge/rviz/rbq_sensors.rviz)로 RViz 를 엽니다:

bash
bash scripts/gazebo.bash --rviz
bash scripts/gazebo.bash --livox --rviz
⚠

WARNING — RBQ 스택 없이는 RViz 가 비어 보입니다

RViz 의 Fixed Frame local_world 는 Gazebo 가 아니라 RBQ 스택이 보냅니다. bash scripts/sim.bash --vision --no-sim 을 함께 띄우거나, Fixed Frame 을 world 로 바꾸세요.
