팔 제어 — C++ 예제 ​

C++ · Python

소스: rbq_sdk/cpp/example/src/arm/

외부 앱에서 RBQ 에 달린 RBA-1 팔을 제어합니다. 예제에는 해 볼 순서대로 번호가 붙어 있습니다. 예제마다 한 가지 일을 하고 끝나며, 팔이 꺼져 있으면 각자 팔을 기동하므로(arm_helper.hpp) 어느 것이든 따로 실행할 수 있습니다.

예제단계하는 일
00_arm_help—SDK 버전을 출력하고, 예제 목록과 실행 방법을 출력합니다
01_arm_state상태팔 관절과 엔드이펙터 상태를 1 초에 두 번 출력합니다. 아무것도 보내지 않습니다
02_arm_power준비팔을 기동하거나, 상태를 출력하거나, 관절 제어 앱이 쥔 관절을 되찾거나, 팔을 멈추고(팔 비상정지) 다시 풉니다
03_arm_gripperLv1그리퍼를 잠시 열거나 닫은 뒤 멈춥니다
04_arm_move_jLv1 (관절 공간)내장 자세나 관절 각도로 MoveJ — 여섯 관절 또는 한 관절, 그 각도로 또는 그 각도만큼
05_arm_move_lLv1 (태스크 공간)위치로 MoveL, 자세로 RotateL, 또는 둘 다. 또는 짧은 상대 이동 순서
06_arm_high_levelLv1 (태스크 공간)이 PC 의 게임패드로 엔드 이펙터를 움직입니다
07_arm_low_levelLv0 (관절)팔 관절 여섯 개를 가져와 500 Hz 로 관절 레퍼런스를 보낸 뒤 돌려줍니다. 직접 만든 FK·IK 는 my_arm 을 고칩니다
08_arm_torqueLv0 (토크)팔 관절 여섯 개를 가져와 500 Hz 로 관절 토크를 보냅니다: 중력 보상과 출발 자세로 당기는 스프링

WARNING

팔은 사람이 다칠 만큼 빠르게 움직입니다. 팔이 닿는 범위에 사람이 없게 하고, 작은 동작부터 시작하고, 원격 비상정지를 손에 두세요.

사전 요구사항 ​

  • SDK 설치. 한 번도 설치하지 않은 PC 라면 C++ SDK 개요를 따르고, 아니면 바로 빌드로 넘어갑니다. 빌드가 The SDK installed in … is not this checkout's SDK 로 멈추면 SDK 를 다시 설치하고 다시 빌드합니다.

    bash

sudo bash scripts/build.bash

  • 로봇 스택이 실행 중 — 이 PC 의 시뮬레이터, 또는 이 PC 에서 닿는 로봇.

  • RBA-1 팔을 단 RBQ, 서 있는 상태. 시뮬레이터에서는 bash scripts/sim.bash --robot rba-1로 띄우고, 웹 UI 에서 Auto Start → STAND 까지 진행합니다.

빌드 ​

bash

bash scripts/build.bash

바이너리: bin-x86_64/00_arm_help … bin-x86_64/08_arm_torque, bin-x86_64/my_arm, 그리고 시험 도구 bin-x86_64/arm_cli(ArmClient 참조)

예제는 모두 이 폴더(rbq_sdk/cpp/example/)에서 실행합니다 — 이 페이지의 명령은 ./bin-x86_64/ 로 시작합니다.

모든 예제는 대상(target)을 첫 인자로 받습니다. 대상은 예제가 연결하는 곳, 곧 상태를 읽고 명령을 보낼 로봇 스택입니다. 빼면 시뮬레이터에 연결하고, robot(-r)을 주어야 로봇에 명령을 보냅니다.

대상연결하는 곳
sim(-s), 또는 생략이 PC 의 시뮬레이터
robot(-r)192.168.0.10 의 로봇. 이 PC 에서 로봇에 닿는 네트워크 장치를 알아서 고릅니다 — 먼저 로봇 와이파이나 케이블에 연결하세요
enp3s0 같은 이 PC 의 네트워크 장치 이름그 장치로 닿는 로봇 스택(rbq 예제와 같은 방식). 이름은 ip -br link 로 확인합니다

이 중 어디에도 해당하지 않는 단어는 대상이 아닙니다. 예제는 시뮬레이터에 연결하고 그 단어를 다음 인자로 읽으며, 그 인자가 틀리면 no target given, so '…' was read as an argument 를 출력하고 멈춥니다.

00_arm_help가 예제 목록과 이 대상들을 출력하고, 예제마다 -h 로 자세한 설명을 출력합니다. 다른 예제를 실행하는 동안 01_arm_state를 터미널 하나에 켜 두세요.

호출이 성공하면 예제는 [arm] MoveJDelta done in 0.91 s 처럼 한 줄만 출력합니다. 실패하면 응답 코드와 그 뜻, 다음에 할 일을 출력합니다. 코드는 ArmClient 에 있습니다.

1. 팔 상태 — 01_arm_state ​

팔 관절 여섯 개와 그리퍼의 이름, 보드 상태, 소유 슬롯, 위치·속도·토크의 레퍼런스와 측정값, 게인, 그리고 엔드이펙터 자세를 1 초에 두 번(2 Hz) 출력합니다. 읽기만 하고 로봇에 아무것도 보내지 않습니다.

bash
cd ~/RBQ/rbq_sdk/cpp/example
./bin-x86_64/01_arm_state [target]

[target] 은 연결할 곳입니다. 이 PC 의 시뮬레이터는 sim 또는 생략, 로봇은 robot — 대상 표를 보세요.

rt/rbq/arm_joint(ArmJointInfo_)와 rt/rbq/arm_ee(TaskInfo_)를 구독해 Ctrl+C 까지 출력합니다.

열의미
nameJ0–J5(J0 어깨 요, J1 어깨 피치, J2 팔꿈치 피치, J3 팔꿈치 롤, J4 손목 피치, J5 손목 롤), GRP(그리퍼)
stat / err보드 상태(NON CON HOM RUN) / 오류(OK JAM FLT TMP CUR BIG INP)
owner그 관절을 구동하는 앱 슬롯
ref_pos / pos관절이 따라가는 위치 레퍼런스 / 측정 위치 [deg]
ref_vel / vel속도 레퍼런스 / 측정 속도 [deg/s]
ref_torque / torque피드포워드 토크 레퍼런스 / 측정 토크 [Nm]
kp / kd관절에 실제로 걸린 게인 [Nm/rad], [Nm·s/rad]
cur / T(b/c)전류 [A] / 보드·코일 온도
EE 줄몸통 좌표계의 엔드이펙터 위치 [m]와 roll/pitch/yaw [deg]

팔을 기동하기 전에는 kp 가 0 입니다.

2. 팔 기동 — 02_arm_power ​

팔을 기동(축 초기화와 레퍼런스 송신 시작)하거나, 상태를 출력하거나, 관절 제어 앱이 쥔 관절을 되찾거나, 팔을 멈추고 다시 풉니다.

bash
./bin-x86_64/02_arm_power [target] [on|status|release|estop|clear]
동작하는 일
on(기본값)팔이 꺼져 있으면 기동(AutoStart)하고 켜질 때까지 기다립니다
status팔 상태를 출력합니다(GetState): arm_type, con_start, task_control, estop, pose, joint_owner, sdk_slot 과 ArmClient 에 적은 나머지
release관절 제어 앱이 쥔 팔 관절을 모두 팔 제어기로 돌려줍니다(ReleaseJoints)
estop팔 비상정지(EmergencyStop)
clear팔 비상정지를 풉니다(ClearEmergencyStop)

팔 비상정지. 팔 관절에 감쇠만 남고 자세를 붙잡는 힘이 빠집니다. 팔은 자기 무게로 천천히 내려앉고, 밀리거나 무언가에 부딪히면 떨어지거나 버티지 않고 밀려납니다.

  • clear(또는 AutoStart)까지 이어집니다. 그동안 동작 호출은 모두 7108 로 거절되고, 예제는 the arm is in emergency stop - clear it first 를 출력하고 멈춥니다. 그리퍼는 그대로 됩니다.
  • 로봇 비상정지(앱의 E-STOP, SportClient::Damp, rt/rbq/cmd/emergency)도 팔을 같은 방식으로 멈춥니다. 팔만 건 비상정지와 달리 다리가 다시 일어서면 저절로 풀리고, 팔은 내려앉은 자세를 붙잡습니다. 그 전에 clear 로 풀어도 됩니다. 팔 비상정지는 로봇에 상관없이 팔만 멈춥니다.
  • clear 뒤에는 내려앉은 자세를 붙잡습니다. 태스크 공간 이동 전에 Ready 로 옮깁니다(04_arm_move_j 1).

3. 그리퍼 — 03_arm_gripper ​

그리퍼를 정한 시간(기본 1 초) 동안 열거나 닫은 뒤 멈춥니다.

bash
./bin-x86_64/03_arm_gripper [target] <action> [seconds]

# 1 초(기본값) 동안 닫은 뒤 멈추기:
./bin-x86_64/03_arm_gripper sim 1

action 은 0 또는 open, 1 또는 close 입니다. 그리퍼는 멈출 때까지 계속 움직입니다. 이 예제는 seconds(0 < seconds ≤ 5) 뒤에 멈춥니다.

그리퍼는 게임패드로도 움직이고(6), 팔 관절을 쥔 앱도 그리퍼를 열고 닫을 수 있습니다(7).

4. 관절 공간 이동 — 04_arm_move_j ​

팔을 내장 자세 네 개 중 하나로, 또는 관절 각도로 옮깁니다. 팔 제어기가 관절을 함께 움직여 같은 때에 도착시킵니다.

bash
./bin-x86_64/04_arm_move_j [target] <pose>
./bin-x86_64/04_arm_move_j [target] [abs|rel] <J0 J1 J2 J3 J4 J5> [seconds | vel=<deg/s> acc=<deg/s^2>]
./bin-x86_64/04_arm_move_j [target] [abs|rel] J<n> <degrees>      [seconds | vel=<deg/s> acc=<deg/s^2>]

./bin-x86_64/04_arm_move_j sim 1                      # Ready
./bin-x86_64/04_arm_move_j sim home                   # Folding
./bin-x86_64/04_arm_move_j sim 0 120 -60 0 -60 30 4   # 여섯 관절을 이 각도로 4 초 동안
./bin-x86_64/04_arm_move_j sim J1 120 2               # J1 만 120 도로 2 초 동안
./bin-x86_64/04_arm_move_j sim rel J4 -15 vel=20      # J4 만 지금에서 -15 도, 20 도/초 이하로

인자 없이 실행하면 자세 목록과 이 형식들을 보여 줍니다.

자세는 번호나 이름으로, 대소문자 구분 없이 줄 수 있습니다 — 0 과 home 은 같습니다.

번호이름각도 J0–J5 [deg]설명
0home0 0 0 0 0 0홈 / 보행 자세
1ready0 140 -70 0 -70 0태스크 공간 이동의 시작 자세. 팔을 기동한 뒤 첫 이동은 여기로 합니다
2straight0 90 -180 0 0 0팔을 위로 쭉 편 자세
3pickup0 150 -100 0 40 0바닥의 물건을 잡기 위한 자세

MoveJ() 자체는 자세 이름을 받습니다: ARM_POSE_FOLDING, ARM_POSE_READY, ARM_POSE_STRAIGHT, ARM_POSE_PICKUP_READY. 번호와 이름은 예제가 받아 주는 것입니다.

예제는 팔이 어느 자세에 있든 고른 자세로 바로 갑니다.

관절 각도로 [deg]:

인자뜻
abs(기본값)각도가 관절이 갈 곳입니다(MoveJ)
rel각도가 관절이 지금 지령에서 돌 만큼입니다(MoveJDelta)
J0 … J5관절마다 하나씩, 각도 여섯 개
J<n> <degrees>관절 n(J0–J5)만. 다른 관절은 그대로입니다
seconds움직이는 관절이 모두 이 시간에 도착합니다. 0.5~20 초
vel= acc=또는 가장 빠른 관절이 이 값을 넘지 않는 가장 짧은 시간을 로봇이 고릅니다 — 속도 참고

관절 범위는 J1 0°~180°, J2 −180°~2°, 나머지 −360°~360° 입니다. Ready 는 0 140 -70 0 -70 0 입니다. Ready 각도에서 끝난 이동은 Ready 로 쳐서, 그 뒤에 ControlStart() 가 됩니다.

  • 관절 이동을 시작하기 전에 로봇이 그 경로를 따라가 봅니다. 팔이 몸통이나 다리에 2 cm 안으로 다가가면 출발하지 않고 Wait() 가 7106 을 돌려줍니다. 엔드 이펙터를 로봇에서 떼어 놓은 뒤(6 절) 다시 보냅니다.
  • 이동 중에 어느 관절이 팔을 버티는 데 드는 힘보다 훨씬 세게 밀면(충돌) 이동을 멈추고 Wait() 가 7105 를 돌려줍니다. GetState 의 collision_joint 가 그 관절입니다.

5. 태스크 공간 이동 — 05_arm_move_l ​

엔드이펙터를 위치로, 자세로, 또는 둘 다로 옮기거나, 짧은 상대 이동 순서를 실행합니다.

bash
./bin-x86_64/05_arm_move_l [target]                                                 # 데모
./bin-x86_64/05_arm_move_l [target] [abs|rel] pos  <x y z>                [seconds | vel= acc=]
./bin-x86_64/05_arm_move_l [target] [abs|rel] ori  <roll pitch yaw>       [seconds | ang_vel= ang_acc=]
./bin-x86_64/05_arm_move_l [target] [abs|rel] pose <x y z roll pitch yaw> [seconds | vel= acc= ang_vel= ang_acc=]

# 데모: 위로 2 cm, 앞으로 2 cm, pitch +10 도, 그다음 같은 길로 되돌아오기:
./bin-x86_64/05_arm_move_l sim

# 위치 [m] 로 3 초 동안 - 자세는 그대로:
./bin-x86_64/05_arm_move_l sim pos 0.80 0 0.20 3

# pitch 30 도로 2 초 동안 - 위치는 그대로:
./bin-x86_64/05_arm_move_l sim ori 0 30 0 2

# 지금 자리에서 5 cm 뒤로, 2 초 동안:
./bin-x86_64/05_arm_move_l sim rel pos -0.05 0 0 2
모드호출움직이는 것
posMoveL(x, y, z, …)위치. 자세는 그대로입니다
oriRotateL(roll, pitch, yaw, …)자세. 위치는 그대로입니다
poseMoveL(x, y, z, roll, pitch, yaw, …)둘 다

abs(기본값)는 손끝이 갈 곳을, rel 은 움직일 만큼을 줍니다(MoveLDelta, RotateLDelta). 위치는 지금 지령 위치에 더하므로 반복해도 어긋나지 않습니다. 각도는 지금 측정한 roll / pitch / yaw 에 더하므로, 여러 번 돌리면 한 번에 0.몇 도씩 쌓일 수 있습니다.

단어를 빼면 숫자 세 개는 pos, 여섯 개는 pose 입니다. 위치 [m] 와 roll / pitch / yaw [deg] 는 몸통 좌표이고, 01_arm_state 의 EE 줄에 나오는 값과 같습니다. x 앞, y 왼쪽, z 위이고, 자세는 z(yaw), y(pitch), x(roll) 순으로 돕니다. seconds(0.5~10 초)를 주거나 속도 상한을 줍니다.

태스크 공간 제어가 꺼져 있으면 먼저 Ready 로 가서 켭니다(ControlStart). 이미 켜져 있으면(GetState 의 task_control 이 1) 팔이 지금 자리에서 바로 움직입니다.

엔드 이펙터는 6 절의 작업공간 안에서만 움직입니다. 가장자리에 닿은 이동은 그 자리에서 멈추고 Wait() 가 7107 을 돌려줍니다.

6. 게임패드 태스크 공간 제어 — 06_arm_high_level ​

이 PC 의 게임패드로 엔드이펙터를 움직입니다. 스틱이 속도를 정하고, 1 초에 50 번 보냅니다.

bash

동작 방식 ​

  1. 팔을 기동하고 Ready 로 갑니다.
  2. 앱 슬롯 22 용으로 rt/rbq/ref/motion/_22의 Publisher<MotionRef_>와 rt/rbq/cmd/motion/owner/_22의 Publisher<JointOwnershipCmd_>를 만들고, rt/rbq/arm_joint를 구독합니다.
  3. rt/rbq/arm_joint에서 팔 관절 여섯 개의 ref_position, kp, kd를 읽습니다.
  4. 팔이 이미 따라가는 값과 같은 첫 레퍼런스를 보낸 뒤 arm_joint[0..5] = true인 JointOwnershipCmd_를 보냅니다. 다리와 그리퍼는 로봇이 계속 맡습니다.
  5. 팔이 쓰던 게인 그대로 arm_joint[]를 500 Hz 로 발행하며, 고른 관절을 부드러운(코사인) 경로로 갔다가 돌아오게 합니다.
  6. 마지막 레퍼런스를 0.2 초 유지한 뒤 arm_joint[0..5] = false를 보내고 종료합니다. Ctrl+C 를 누르면 그 자리에서 멈추고 그 자세로 돌려줍니다.

1–4 와 6 은 arm_helper::JointStream(arm_helper.hpp)이, 5 는 07_arm_low_level.cpp 의 Controller 가 합니다.

    cpp
    // Your own kinematics - in this file or in your own library.
void MyFK(const float q[kArmJoints], float p[3]);                                 // joint angles -> end-effector position
bool MyIK(const float p[3], const float seed[kArmJoints], float q[kArmJoints]);  // false when p is out of reach

struct Controller {
    float p0[3];             // end-effector position at the start
    float qLast[kArmJoints]; // last joint references - the seed of the next IK

    void Start(const ArmState &s, JointStream &arm)
    {
        (void)arm;
        std::copy(s.qRef, s.qRef + kArmJoints, qLast);
        MyFK(s.qRef, p0);
    }

    bool Update(double t, const ArmState &s, const Pad &pad, Command &cmd, JointStream &arm)
    {
        (void)s;
        (void)pad;
        (void)arm;
        const double T = 8.0;
        if (t > T) return false;

        // >>> YOUR ALGORITHM: the end effector 5 cm up and back down in T seconds
        const float lift = 0.05f * 0.5f * static_cast<float>(1.0 - std::cos(2.0 * M_PI * t / T));
        const float target[3] = {p0[0], p0[1], p0[2] + lift};
        if (MyIK(target, qLast, cmd.q))   // writes the joint references into cmd.q
            std::copy(cmd.q, cmd.q + kArmJoints, qLast);
        else
            std::copy(qLast, qLast + kArmJoints, cmd.q);   // out of reach: stay where it is
        // <<< YOUR ALGORITHM
        return true;
    }
};

관절 명령과 토크 레퍼런스 ​

Update 는 매 틱 cmd 를 받습니다. main 이 보내는 관절 명령으로, 관절마다 위치 q, 속도 dq, 토크 tau, 게인 kp, kd 가 들어 있습니다. 각 관절 보드는 이것을 모터 토크로 바꿉니다:

text
motor torque = kp × (q − q_measured) + kd × (dq − dq_measured) + tau

main 은 부르기 전에 cmd 를 채워 두므로, 필요한 것만 바꾸면 됩니다:

값미리 채워지는 값매 틱 새로
q지난 틱에 보낸 위치(처음에는 시작 자세)아니요, 그대로 남음
dq, tau0예
kp팔 기본값: J0, J1 2632 Nm/rad, J2–J5 1190예
kd팔 기본값: J0, J1 21 Nm·s/rad, J2–J5 9.5예

아래 세 가지는 모두 같은 사인 궤적을 따라갑니다. >>> YOUR ALGORITHM 과 <<< YOUR ALGORITHM 사이의 이 루프 안에 하나를 넣습니다:

cpp
const float T = 4.0f, w = 2.0f * float(M_PI) / T, amp = 10.0f * 0.0174533f;
if (t > 2 * T) return false;
for (int i = 0; i < kArmJoints; i++) {
    const float qDes  = q0[i] + amp * std::sin(w * float(t));   // target position [rad]
    const float dqDes = amp * w * std::cos(w * float(t));       // target velocity [rad/s]
    // one of 1, 2, 3 below
}

1. 위치 제어, 중력 보상 없음. 관절 보드가 PD 로 위치를 따라갑니다:

cpp
cmd.q[i]  = qDes;
cmd.dq[i] = dqDes;    // optional: the damping then works around the target velocity and the arm lags less
cmd.kp[i] = 1000.f;   // your gains - leave these two lines out for the arm's own
cmd.kd[i] = 10.f;
// cmd.tau stays 0

중력은 kp 가 오차를 만들어 버티는 방식이라, kp 를 낮출수록 팔이 처집니다.

2. 위치 제어, 중력 보상 있음. 1 에 중력 토크를 앞먹임으로 더합니다:

cpp
cmd.q[i]   = qDes;
cmd.dq[i]  = dqDes;
cmd.kp[i]  = 300.f;          // tau holds the arm against gravity, so a lower kp does not sag
cmd.kd[i]  = 10.f;
cmd.tau[i] = s.gravity[i];   // gravity torque as a feed-forward

새로 생긴 줄은 tau 하나입니다. 중력을 앞먹임이 맡으므로 kp 는 목표로 되돌리는 힘만 맡고, 게인을 낮춰 팔을 무르게 해도 처지지 않습니다(임피던스 제어).

3. 토크 제어. 관절 보드의 위치 제어를 끄고, 보낸 토크만 관절에 걸립니다:

cpp
cmd.kp[i]  = 0.f;            // the joint board's position control off
cmd.kd[i]  = 0.f;
cmd.q[i]   = s.q[i];         // not used with kp 0 - keeps the hand-back smooth
cmd.dq[i]  = 0.f;
cmd.tau[i] = s.gravity[i] + 300.f * (qDes - s.q[i]) + 10.f * (dqDes - s.dq[i]);   // the whole torque is yours

tau 에는 어떤 토크든 넣을 수 있습니다 — 예를 들어 5 Nm 를 걸려면 s.gravity[i] + 5. my_arm sim torque 가 들어 있는 사인 궤적을 이렇게 움직입니다(J0, J1 300 Nm/rad·10 Nm·s/rad, J2–J5 150·5).

q, dqkp, kdtau
1. 위치목표원하는 게인, 또는 팔 기본값0
2. 위치 + 중력 보상목표원하는 게인s.gravity
3. 토크s.q, 00직접 만든 토크(s.gravity 포함)
  • cmd 는 관절마다 따로라서 섞을 수 있습니다 — 루프 안에서 J0 만 토크 제어, 나머지는 위치 제어. 바꾸지 않은 관절은 팔 기본 게인으로 지금 자세를 유지합니다.
  • 토크 제어에서 s.gravity 를 빼면 팔이 떨어지고, 감쇠 항이 없으면 관절이 계속 빨라집니다.
  • 프로그램의 토크 제어는 네트워크를 거쳐 500 Hz 로 돌므로, 관절 보드보다 낮은 게인에서 불안정해집니다. 단순히 무른 팔이 목적이면 2 가 낫습니다. 시뮬레이터에서 들어 있는 토크 사인은 위쪽 끝에서 최대 약 5°, 나머지에서 약 1° 늦습니다.
  • Update 가 false 를 돌려주면 main 이 팔 기본 게인으로 되돌려 그 자리에서 관절을 돌려줍니다.

게인 ​

프로그램이 관절을 쥐고 있는 동안 각 관절은 레퍼런스를 중심으로 한 스프링·댐퍼처럼 움직입니다: 토크 = kp × (레퍼런스 − 각도) + kd × (속도 레퍼런스 − 속도) + 앞먹임 토크. JointStream 은 팔이 이미 쓰는 게인으로 시작하고, arm.SetGains(kp, kd) 는 그 뒤의 모든 Send() 에 쓸 게인을 바꿉니다.

팔이 쓰는 게인(s.kp, s.kd)에서 시작해 비율로 바꾸세요:

cpp
void Start(const ArmState &s, JointStream &arm)
{
    float kp[kArmJoints], kd[kArmJoints];
    for (int i = 0; i < kArmJoints; i++) {
        kp[i] = 0.5f * s.kp[i];   // 절반의 강성
        kd[i] = s.kd[i];
    }
    arm.SetGains(kp, kd);
    std::copy(s.qRef, s.qRef + kArmJoints, q0);
}

8. 토크 제어 — 08_arm_torque ​

팔 관절 여섯 개를 가져와 레퍼런스 대신 관절 토크를 1 초에 500 번 보냅니다: 로봇이 계산한 중력 토크에 각 관절을 출발 자세로 당기는 스프링을 더합니다. 강성을 0 으로 주면 중력만 보상합니다 — 팔이 떠 있고, 밀면 민 자리에 머뭅니다.

팔이 있는 자리에서 시작하므로, 원하는 자세로 먼저 옮겨 두세요(예: 04_arm_move_j). 접힌 자세(home, 또는 팔을 막 기동한 직후)에서만 먼저 Ready 로 옮깁니다.

토크 모드 ​

arm.SendTorque(torque) 는 토크 여섯 개 [Nm] 를 kp 0 과 작은 감쇠 kd 로 보냅니다: J0, J1 5 Nm·s/rad, J2–J5 2.5(kTorqueModeKd). 다른 kd 는 두 번째 인자로 줍니다. 팔을 붙잡는 것은 보낸 토크뿐입니다:

cpp
const ArmState s = arm.State();
float torque[kArmJoints];
for (int i = 0; i < kArmJoints; i++)
    torque[i] = s.gravity[i] + myTorque[i];   // s.gravity 를 빼면 팔이 떨어집니다
arm.SendTorque(torque);
  • s.gravity 는 rt/rbq/arm_gravity 에서 옵니다: 측정 각도에서 팔을 붙잡는 토크입니다. 로봇이 팔 모델로 계산하며 몸통을 수평으로 보므로, 몸통이 기울면 팔이 조금 흘러내립니다.
  • 각 토크는 J0, J1 ±60 Nm, J2–J5 ±25 Nm 로 잘립니다.
  • 0.2 초 동안 토크가 오지 않으면 로봇이 직접 중력 토크와 감쇠를 보냅니다. 팔은 떨어지지 않고 그 자리에 떠 있습니다.
  • arm.Send(q) 를 부르면 위치 제어로 돌아갑니다. 끝날 때 arm.Stop() 은 위치 게인으로 그 자리에 팔을 붙잡은 뒤 관절을 돌려줍니다.
  • 7 절과 같이 팔 제어기의 작업 영역·충돌 검사는 돌지 않습니다.

ArmClient ​

ArmClient 는 SportClient 와 같은 방식입니다 — 요청/응답 서비스(rt/api/arm/request, rt/api/arm/response)이고, 호출마다 로봇이 답할 때까지 기다립니다. 예제 02~05 가 이것을 씁니다.

각도는 rad, 각속도는 rad/s 입니다 — SportClient 와 팔 토픽과 같습니다. 예제는 명령줄에서 도(°)로 받아 rad 로 바꿔 부릅니다.

코드를 짜지 않고 호출을 시험해 보려면 시험 도구 ./bin-x86_64/arm_cli [target] 을 실행합니다. 예제가 아니라 시험 도구입니다 — > 입력 줄에 get_state, auto_start, go_ready, ee_up, gripper_open, estop 같은 명령 이름을 넣으면 그 호출을 실행합니다.

7106Wait(): 관절 이동이 출발하지 않음 — 경로가 몸통이나 다리에 닿음
7107Wait(): MoveL* 이 작업공간 가장자리에서 멈춤
7108팔 비상정지 중 — 먼저 ClearEmergencyStop(). Wait(): 비상정지로 멈춘 동작
7109준 시간이 너무 짧음: 최대 속도를 넘는 이동. GetState 의 motion_time 에 그 이동에 필요한 가장 짧은 시간이 있습니다

동작 명령은 로봇이 받는 즉시 돌아옵니다. Wait() 는 팔이 도착했을 때 돌아오고, Stop() 은 동작을 중간에 멈춥니다. 팔이 아직 움직이는 동안 보낸 동작 명령은 7101 로 거절됩니다.

게인 ​

SetGains(kp, kd) 는 팔 제어기가 MoveJ, MoveL*, 게임패드 제어(6 절)에 쓰는 관절 게인을 정합니다 — kp [Nm/rad] 여섯 개와 kd [Nm·s/rad] 여섯 개, J0 부터:

std::array<float, 6> kp = {2000.f, 2000.f, 900.f, 900.f, 900.f, 900.f};
std::array<float, 6> kd = {21.f, 21.f, 9.5f, 9.5f, 9.5f, 9.5f};
arm.SetGains(kp, kd);   // 기본보다 무르게
// ...
arm.ResetGains();       // 기본값으로

  • 범위를 벗어난 값이 하나라도 있으면 호출 전체가 3204 로 거절되고 아무것도 바뀌지 않습니다.
  • 새 게인은 0.5–2 초에 걸쳐 걸리며, 움직이는 중에도 받습니다. ResetGains() 나 AutoStart() 전까지 유지됩니다.
  • kp 가 낮을수록 팔이 목표를 덜 바짝 따라가고, 밀면 더 밀립니다.

  • 앱이 관절을 쥐고 있는 동안에는 3205 로 거절됩니다. 그 앱에서 JointStream::SetGains로 바꾸세요.
  • GetState 에 정한 게인과 기본값이 있습니다. 지금 실제로 걸린 게인은 rt/rbq/arm_joint 에 있습니다.

속도 ​

이동마다 시간을 주거나 속도 상한을 줍니다. 상한을 주면 로봇이 모든 상한을 넘지 않는 가장 짧은 시간을 고릅니다. 0 이거나 뺀 상한은 기본값을 씁니다.

최대를 넘는 상한은 3204 로 거절됩니다. 시간을 줄 때도 그 이동이 최대를 넘지 않아야 합니다. 더 짧으면 7109 로 거절되고, GetState 의 motion_time 에 그 이동에 필요한 시간이 있습니다. 예제는 이것을 출력합니다: 0.5 s is too fast for this move … This move needs at least 0.53 s.

로봇이 상한으로 고르는 시간은 최대 60 초입니다. Wait() 는 기본 15 초 뒤에 포기하므로, 긴 이동은 더 긴 시간을 주세요.

이 미리보기의 한계 ​

  • 관절 위치·토크 한계, 속도 상한, 게인 범위는 액추에이터 사양이 확정될 때까지 임시값입니다.
  • 중력 토크는 몸통을 수평으로 보고 계산합니다.
  • 충돌 검사는 시뮬레이터 모델의 몸통·다리 모양을 씁니다. 상판에 실은 장비는 모델에 없습니다 — 그래서 그리퍼를 로봇 앞에만 둡니다.
  • 충돌 토크 한계는 임시값이며 아직 실기에서 재지 않았습니다.
  • 미션 단계 명령(물건 잡기, 문 열기)은 별도 클라이언트로 추가할 예정입니다.
