# AGENTS.md — RBQ Controller

Guidance for AI coding agents (and humans) working on this app. Code comments are stripped from the
published tree on purpose; this file carries the context that comments would have. Read it before
changing anything.

## Layout

| Path | What |
|---|---|
| `src/app/` | Screens (expo-router, one file per route) |
| `src/components/` | UI. `components/ui/` holds shared widgets — every export there is shown in the in-app gallery (`/widgets`) and a test enforces it |
| `src/lib/` | Robot I/O, gamepad, platform adapters — no React |
| `src/store/` | zustand stores (several persisted) |
| `src/modules/` | Optional feature modules. `registry.ts` holds empty extension points; `installed.ts` imports each module once (empty in this repository) |
| `src/rb/` | Design system, **compiled** (`.js` + `.d.ts`). Use it, don't edit it — replace a component with your own if you need to change it |
| `src-tauri/` | Desktop shell (Linux/Windows/macOS) |
| `tools/rbq-web-proxy.js` | Local sidecar for web and desktop builds (CORS, video bridge, Wi-Fi) |
| `modules/`, `plugins/`, `patches/` | Native module, Expo config plugins, `patch-package` patches |

`android/` and `ios/` are generated by `npx expo prebuild` — change `app.json`, `app.config.js`,
`plugins/` or `patches/`, never the generated folders.

## Commands

```bash
npx tsc --noEmit -p .          # typecheck
npx vitest run                 # unit tests
node tools/i18n-check.js       # see "Translations"
npm run web                    # Metro + browser; add ?demo=1 to run without a robot
bash scripts/docker/run.bash   # full builds in Docker → build-out/
```

## Talking to the robot

- One WebRTC peer to the robot, four data channels: `log` (telemetry topics + logs),
  `motion-state` (40-byte joystick frames at 40 Hz), `command` (REST-over-DataChannel) and `estop`.
  `src/lib/connection.ts` creates the offer; `src/lib/rest.ts` routes calls.
- The robot's HTTP API only serves **reads** and WebRTC signaling. Every write (POST/PUT) goes through
  the `command` channel (`commandBus.dcCommand`: idempotent message id, 1 s resend, 8 s deadline).
  Sending a write over HTTP returns 404/405.
- Motion ownership: the robot accepts motion commands only from the current owner; take ownership
  explicitly (the UI does this with a claim), never in a retry loop.
- Authentication: HTTP Basic, user `rbq`, password per robot. `src/lib/auth.ts` reads the stored
  password; on 401 the app shows `RobotAuthPrompt` and saves the answer for the address that
  returned 401 (moved to the robot's serial once it is identified) — never as a shared fallback.
  Passwords are kept in plain app storage (`rbq-robots`), not a keychain. `EXPO_PUBLIC_ROBOT_DEFAULT_AUTH` sets a build-time
  default if you ship to your own fleet.
- Access levels 2/3 (`src/lib/accessLevel.ts`): default code `0000` for both unless `.env` sets
  `EXPO_PUBLIC_LV2_SHA256`/`EXPO_PUBLIC_LV3_SHA256`. They are a UI lock against accidental use, not a security
  boundary — the code hashes ship inside the app.
- The local proxy serves only this machine by default (`--host 127.0.0.1`) and accepts its
  state-changing routes and the `/webrtc` bridge only from its own origin. Keep it that way: it relays
  to a robot without authentication of its own.
- Cameras use a second peer to the robot's streamer (`src/lib/webrtcClient*.ts`).
- Decode binary telemetry by the offsets in `src/lib/robotState.ts` and friends — they are pinned by
  tests with captured frames. Don't "fix" an offset without a real frame.

## Conventions

- **Platform split by file name**: `foo.web.ts` next to `foo.ts`; Metro picks one. Keep both export
  lists identical — a missing export shows up as a blank screen on only one platform.
- **Configuration is environment-driven** (`EXPO_PUBLIC_*`, see `.env.example`). Features whose
  configuration is empty are **hidden, not broken**: remote access, accounts, push, log upload, issue
  reporting, firmware transfer. Follow the same pattern for anything you add that needs a server.
- **Extension points instead of branches.** To add a device- or customer-specific feature, create
  `src/modules/<name>/index.ts`, register into `src/modules/registry.ts` (maintenance tabs, dashboard
  rows/cards, gamepad combos, extra telemetry frames, robot-version labels, other robot kinds, translations) and add one
  import line to `src/modules/installed.ts`. Removing the folder and the line must leave the app building.
- **Translations**: UI strings are Korean source text wrapped in `t('…')`; English lives in
  `src/lib/i18n.en.ts` (modules add theirs with `addTranslations`). `t()` falls back silently, so run
  `node tools/i18n-check.js` — it flags missing keys and strings composed before `t()`.
- **Sliders send on commit, not on change** — sending in `onChange` floods the robot with a command
  per drag frame.
- **Landscape only.** Every React Native `<Modal>` must pass
  `supportedOrientations={MODAL_ORIENTATIONS}` (from `components/ui/overlays.tsx`), or iOS aborts the
  app when the modal opens. The shared `Modal` wrapper already does it.

## Traps (each one has happened)

- **Relative `fetch('/…')` on native crashes release builds.** There is no base URL outside Metro, so
  `fetch` throws synchronously (not a rejected promise). Gate web-only endpoints with
  `Platform.OS === 'web'`. Debug builds never show it.
- **iOS stops rendering a GLView whose opacity is below 1** and it does not recover. Hide the 3D view by
  stacking (z-order), not opacity. After returning from background, remount the `<Canvas>` only.
- **iOS Simulator / Android emulator can't validate 3D** (Three.js + EXGL shows the first frame only).
  Use a device.
- **Desktop Linux (WebKitGTK) can't play WebRTC media.** The desktop build receives camera video through
  the local proxy, which transcodes to MJPEG frames over a WebSocket. Changes to video on desktop go
  through `tools/rbq-web-proxy.js` and `src/lib/desktopVideo.ts`.
- **Steam Deck**: touch arrives as mouse events unless the proxy switches gamescope to passthrough;
  the Gamepad API only exposes the pad after a button press; `requestFullscreen()` kills the WebKitGTK
  webview — use the Tauri window API.
- **Safe area**: the legacy control shell and React Native modals are outside `Screen`'s insets; add
  insets yourself there. Android landscape usually reports zero side insets, so check on iOS.
- **Metro cache** can serve a stale build (wrong version, wrong route root). Use `--clear` when output
  doesn't match the source.
- Persisted stores: renaming a field silently drops users' saved values. Migrate in the store's
  `merge` instead of bumping `version`.
